Reference / Plugin API / definePlugin

definePlugin

Stable

Extends the build and the browser runtime: configuration, injected context, lifecycle hooks and bundled components.

Always wrap the object.

export default definePlugin({ ... }) is the only accepted form. A bare object export is CORALITE-P401.

Signature

export default definePlugin({ name: string config?: Record<string, any> context?: (pluginContext: { app: CoraliteInstance, config: any }) => (instanceContext: CoralitePluginContext) => Record<string, any> server?: CoralitePluginServer client?: CoralitePluginClient dependencies?: string[] modes?: Array<'development' | 'testing' | 'production'> })

Options

Key Type Notes
namestringRequired. Unique across the build and used as the context namespace. P101 when missing, P102 when reserved.
configobjectShared configuration, validated at definition time and overridable when the plugin is registered. P206 for an invalid schema, P207 for an invalid call-time value.
contextfunctionUbiquitous two-phase resolver. Mutually exclusive with server.context and client.context.
serverobjectBuild-time hooks, components and context.
clientobjectBrowser hooks, init and context.
dependenciesstring[]Plugin names that must initialize first. P205 for a malformed list.
modesstring[]Build modes the plugin is active in. Defaults to all three. P204 for an invalid list.

depends is not supported: it was renamed to dependencies, and the old key is P206. rootDir and filePath are resolved by the loader; do not set them by hand.

Context

There are two context mechanisms, and they are mutually exclusive. Mixing them is P211.

Declaration Available in Use for
contextserver, getters, client, slots, stylePure helpers usable on both sides: formatters, translators, read-only clients.
server.contextComponent and page server()Build-only clients: database handles, filesystem readers, API keys.
client.contextComponent and page client()Browser-only helpers: DOM utilities, third-party widgets.

Both forms are curried. Phase one receives plugin-level context once; phase two runs per instance with the page, module and root in scope. Returning an object from phase one instead of a function is P201.

import { definePlugin } from 'coralite' export default definePlugin({ name: 'format', context: ({ config }) => () => ({ formatPrice: (value) => new Intl.NumberFormat(config.locale, { style: 'currency', currency: config.currency }).format(value) }) })

Framework keys win. A plugin key that collides with state, route, refs, signal, emit, observe or root is ignored in favor of the core value, so namespacing is the safe default.

Server hooks

All hooks are asynchronous and may return a patch. A hook that returns nothing leaves the pipeline untouched.

Hook Receives Return
onBeforeBuildapp, buildId, options, addRenderQueue{ options } to patch the build, or nothing.
onAfterBuildresults, error, duration, appNothing; the build is already written.
onPageSetelements, state, page, dataState patch. May return paths to enumerate routes.
onPageUpdateelements, page, newValue, oldValueState patch.
onPageDeletedataNothing.
onComponentSetcomponentState patch.
onComponentUpdatecomponentState patch.
onComponentDeletecomponentNothing.
onBeforePageRendercomponent, state, page, sessionState patch.
onAfterPageRenderresult, sessionExtra CoraliteResult outputs to save.
onBeforeComponentRenderstate, componentId, instanceId, refs, templateState patch merged before render.
onAfterComponentRenderresult, state, componentId, instanceIdAST patch merged after render.

onPageSet is the route contribution point: returning { paths: [...] } adds parameter objects, and duplicates against the page's own paths() are a build error. A non-array value is CORALITE-E407. An unknown server property or a hook that is not a function is P202; Node-only imports in the client block are P203.

Client hooks

The client block is serialized into the browser bundle. It cannot reference module scope, so anything it needs must be imported inside the function or shipped through client.config.

Hook When Notes
initOnce at runtime bootReceives { config, runtime, app, route, onCleanup, store }. Register global listeners and pass their removal to onCleanup.
contextPer instanceTwo-phase resolver injected into client(). Phase one runs before the component loader is ready; create elements in phase two or init.
onBeforeComponentRenderBefore a component rendersCan inspect state and refs; do not mutate the DOM yet.
onAfterComponentRenderAfter a component updateThe place for post-render measurement or third-party attachment.
onDisconnectedWhen a component leaves the DOMRelease resources the plugin attached to that instance.

client.config must be serializable JSON. A function at that position is P302, a non-serializable value is P210, replacing it whole is P209, and referencing module scope from a serialized client function is P301. An unknown client property is P303.

Bundled components

server.components ships component files with the plugin, so a plugin can depend on its own custom elements without the host project copying them.

export default definePlugin({ name: 'feedback', server: { components: ['./components/feedback-button.html'] } })

A missing path fails the build when the component is registered. An invalid server property is P202.

Dependencies and modes

dependencies orders initialization: the named plugins run first and are available through phase-one context. The list is names, not imports, so the host project decides which plugins are registered.

modes limits the plugin to specific build modes. A dev-only overlay, for example, should not be active in production or in the E2E testing mode.

export default definePlugin({ name: 'dev-overlay', modes: ['development'], client: { init ({ onCleanup }) { const badge = document.createElement('div') badge.className = 'dev-overlay' badge.textContent = 'dev' document.body.append(badge) onCleanup(() => badge.remove()) } } })

Diagnostics

  • CORALITE-E107 reports an unknown top-level block.
  • CORALITE-P101 and P102 guard the plugin name.
  • CORALITE-P201 reports a single-phase context resolver.
  • CORALITE-P202 and P303 report unknown server and client properties.
  • CORALITE-P204 and P205 guard modes and dependencies.
  • CORALITE-P211 reports mixed context declarations.
  • CORALITE-P401 reports a bare plugin object.
