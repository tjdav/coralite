Diagnostics

Reference

Every code Coralite can emit, grouped by domain, with its severity, whether coralite fix can repair it, and how to resolve it.

Codes are contracts. They are stable across releases, safe to match in CI, and the same strings appear in coralite check, the JSON report and this page. Filter a run with --code E201, silence a single finding with a pragma, or hand the JSON to an agent.

Working with diagnostics

# Audit the workspace coralite check # Only the codes you are cleaning up right now coralite check --code E201 E202 --only-failed # Machine-readable report for CI or an agent coralite check --format json # Preview and apply automatic repairs coralite fix --dry-run coralite fix --code E201

Every code carries a severity. Errors fail the build; warnings are reported and only fail under --strict. Auto-fixable codes name the AST transformation coralite fix applies, so a repair is deterministic rather than a suggestion.

Component diagnostics can be silenced locally with a pragma comment inside the component file. Config, route and stylesheet errors abort the build and cannot be ignored.

The catalogue from the CLI

The same catalogue that renders this page ships with the framework, so you can query it without leaving the terminal or pull it into tooling:

coralite diagnostics coralite diagnostics --family plugin --fixable coralite diagnostics --search template --format json
