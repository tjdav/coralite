Reference / Component API / slots

slots

Stable

Filters, sorts or rebuilds projected children before they are distributed into the template's slots.

Build time and browser.

The server transform runs while the page is rendered. In the browser, slot content is re-evaluated when tracked state changes, so a transform that reads a counter and sorts by it stays live.

Signature

export const slots: Record<string, (context: CoraliteSlotBuilderContext) => SlotResult> interface CoraliteSlotBuilderContext { name: string nodes: Node[] state: Readonly<Record<string, any>> root: HTMLElement | null refs: (name: string) => HTMLElement | null signal: AbortSignal isServer: boolean } type SlotResult = | Node | Node[] | string | null | undefined | Promise<Node | Node[] | string | null | undefined>

Keys match slot names. default handles children without a slot attribute, and every other key handles <slot name="…">. Content projected into a name the template never renders is dropped, so the slot element is the real contract.

Return values

Return Result
undefinedLeave the projected content untouched.
Array of nodesReplace the projection with these nodes, in order.
Single nodeReplace the projection with one node.
StringReplace the projection with parsed HTML (browser only).
null, '', empty arrayRemove the projection so the slot's fallback content renders.
PromiseResolved on the client; the latest resolution wins and stale ones are discarded.

Filtering

Filtering is the common case: keep matching children, drop the rest. The transform receives parsed nodes, so nodeType and matches are available in both environments.

export const slots = { default: ({ nodes }) => nodes.filter((node) => { if (node.nodeType !== 1) { return true } return node.hasAttribute('data-visible') }) }

Querying slot content

Outside a transform, read projected content through the slots helper on the getter or client context. It never renders anything; it answers questions about what the consumer passed.

Member Returns
slots.has(name?)true when at least one node was projected into the slot.
slots.get(name?)The projected nodes as an array.
slots.count(name?)The number of projected nodes.
slots.namesSlot names declared by the template.
slots.defaultProjected nodes of the default slot.

name defaults to default. Whitespace-only text nodes and framework comments are filtered out, so has() reflects authored content rather than formatting.

export const getters = { iconOnly: ({ slots }) => slots.has('icon') && !slots.has('default') }

Literal content

Add coralite-ignore to a <slot> when projected content must stay exactly as authored: no token interpolation, no custom-element compilation, no hydration, no validation. This is how a code-block keeps source samples from being executed.

<template id="code-block"> <pre><code><slot coralite-ignore></slot></code></pre> </template>

The directive only affects the projection. Fallback content authored inside the slot is component content and is processed normally.

Asynchronous slots

A transform may return a promise. It resolves in the browser after the initial render, so the server sends the untransformed projection and the client replaces it. Use this for content derived from client-only data, not for anything that must exist in the first paint.

Diagnostics

  • CORALITE-E105 reports the legacy (nodes, state) parameter shape; destructure the context instead.
