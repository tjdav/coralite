getters

Stable

Derived state shared by the server render and the browser. Getters read state and compute values; they never store them.

Build time and browser.

Getters evaluate while the page is rendered and again in the browser whenever a tracked state key changes. Keep them pure: the same state must produce the same value in both environments.

Signature

Because refs and root differ between environments, a getter that reads them produces different values on the server and in the browser. That is a hydration mismatch by definition. Use them only in values that are intentionally client-only, or branch explicitly on isServer.

Execution

During the build every getter runs once, in declaration order, and the result is written to state before the template is rendered. In the browser, a getter re-evaluates when a key it read changes. Reading another getter from state links the dependency chain, so a change deep in state invalidates both.

state is read-only inside a getter. Assignment throws. If a value must be stored, compute it in server() or write it from client().

Asynchronous getters

A getter declared async is skipped on the server: the key is set to undefined and the initial HTML renders without it. In the browser it resolves through the async getter cache, tracks dependencies across await points, and discards stale resolutions when state changes mid-flight.

export const attributes = { query: { type: String, default: '' } } export const getters = { results: async ({ state, signal }) => { if (!state.query) { return [] } const response = await fetch(`/api/search?q=${encodeURIComponent(state.query)}`, { signal }) return response.json() } }
Async getters do not exist on the server.

The rendered HTML contains empty output for that token, and reactive DOM updates arrive after the fetch resolves. For data that must be present at first paint, load it in server(); for interaction-driven data, an async getter is the correct tool.

No passthrough getters

A getter whose body is state.someField is dead code. The field is already a flat template token, so use {{ someField }} directly. Keep getters for values that are actually computed.

export const getters = { displayName: ({ state }) => state.name }
<span>{{ name }}</span>

Parameter shape

Getters receive one context object. Destructure it, or name the parameter and read from it. Naming it state without destructuring is the common mistake: the parameter is the context, not state, and is reported as CORALITE-E105.

export const getters = { total: (state) => state.items.length }
export const getters = { total: ({ state }) => state.items.length, label: (context) => `${context.state.total} items` }

Plugin context

Isomorphic plugin keys from top-level context are available on the getter context. Server-only plugin context is not: values it produced must be written to state in server() and read from state here. Development builds warn when a getter reaches for a server-only plugin key.

Diagnostics

  • CORALITE-E105 reports the wrong parameter shape or context.attributes.
  • CORALITE-W401 reports a getter that nothing reads.
