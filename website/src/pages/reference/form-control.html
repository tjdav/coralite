Reference / Component API / formControl

formControl

Stable

Turns a component into a real form control: it participates in submission, reset, disabled state and the browser's validation UI.

Browser only.

The flag is read at build time to emit the right module, but the behavior comes from ElementInternals, which only exists in the browser. During SSR the component renders its normal markup and the form helpers are absent.

Signature

export const formControl: boolean // legacy alias, still accepted export const formAssociated: boolean

formControl wins when both are declared. The value must be a boolean; anything else is CORALITE-E107. There is no per-instance opt-in: the export applies to every host element of the component.

Client helpers

The client context always exposes these members, but they only have an effect when the component is form-associated. Without the flag, internals is null and development builds warn when setFormValue or setValidity is called.

Member Purpose
internalsThe host ElementInternals instance.
setFormValue(value, state?)Sets the value submitted with the form. The optional second argument is the state restored by the browser.
setValidity(flags?, message?, anchor?)Sets the ValidityStateFlags, the message shown by the browser, and the element the message points at.
checkValidity()Runs constraint validation without showing UI.
reportValidity()Runs constraint validation and shows the browser's message.
validityThe current ValidityState.
validationMessageThe message the browser would show.
formThe associated HTMLFormElement, or null when the element is not inside a form.
onFormReset(callback)Runs when the form is reset. Returns a disposer.
onFormDisabled(callback)Receives true or false when a disabled ancestor form or fieldset changes.
onFormRestore(callback)Receives the restored value and the mode, 'restore' or 'autocomplete'.

Value synchronization

The browser does not read component state. Call setFormValue whenever the submitted value changes, including once at mount, or the form submits the empty default. It accepts a string, a File or FormData for richer controls, or null to clear the submitted value.

export const formControl = true export const attributes = { value: { type: String, default: '' } } export function client ({ state, refs, signal, setFormValue }) { const input = refs('input') setFormValue(state.value) input.addEventListener('input', () => { state.value = input.value setFormValue(state.value) }, { signal }) }

Validation

setValidity takes standard ValidityStateFlags: valueMissing, typeMismatch, patternMismatch, tooLong, tooShort, rangeUnderflow, rangeOverflow, stepMismatch, badInput, customError. An empty object clears the error.

function syncValidity ({ state, refs, setValidity }) { if (!state.value && state.required) { setValidity({ valueMissing: true }, 'This field is required.', refs('input')) return } if (state.value.length < 3) { setValidity({ tooShort: true }, 'Use at least three characters.', refs('input')) return } setValidity({}) }

The anchor element is what the browser focuses and scrolls to when it reports the error. Point it at the visible input inside the component, not at the host, otherwise the tooltip has nowhere to attach.

There is one automatic bridge. If an attribute named value fails schema validation, Coralite maps state.errors.value to { customError: true } unless setValidity has already been called manually. Every other attribute error stays in state.errors and the error_* tokens; map those to validity yourself when the browser must report them.

Reset and disabled

A native reset does not know about state, so restore it yourself. Disabled propagation is the other half: a disabled fieldset must visibly disable the inner control, and that is not automatic for light-DOM markup.

export function client ({ state, refs, onFormReset, onFormDisabled }) { const input = refs('input') onFormReset(() => { state.value = '' input.value = '' }) onFormDisabled((disabled) => { state.disabled = disabled input.disabled = disabled }) }

Restore

onFormRestore covers browser-driven restoration: history navigation and autofill. The mode tells you which one fired, so a component can re-run its own formatting after autofill instead of trusting the raw value.

export function client ({ state, setFormValue, onFormRestore }) { onFormRestore((value, mode) => { state.value = mode === 'autocomplete' ? value.trim() : value setFormValue(state.value) }) }

Complete example

<template id="quantity-input"> <button ref="decrease" type="button" aria-label="Decrease quantity">−</button> <input ref="input" type="number" min="1" value="{{ value }}"> <button ref="increase" type="button" aria-label="Increase quantity">+</button> </template> <script type="module"> export const formControl = true export const attributes = { value: { type: Number, default: 1 } } export function client ({ state, refs, signal, setFormValue, setValidity, onFormReset }) { const input = refs('input') const commit = (next) => { state.value = Math.max(1, next) input.value = state.value setFormValue(String(state.value)) setValidity({}) } refs('decrease').addEventListener('click', () => commit(state.value - 1), { signal }) refs('increase').addEventListener('click', () => commit(state.value + 1), { signal }) input.addEventListener('change', () => commit(Number(input.value)), { signal }) onFormReset(() => commit(1)) setFormValue(String(state.value)) } </script>

Inside a form, the component submits under its name attribute like any native control. The host must carry that attribute in the page markup; it is not something setFormValue can supply.

Diagnostics

  • CORALITE-E107 reports a non-boolean formControl or formAssociated value.
