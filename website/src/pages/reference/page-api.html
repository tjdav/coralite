Page API

Stable

A page is the document and one controller script. It enumerates routes, loads data, and composes components without owning their internals.

Pages use the same flat named exports as components, with a smaller set. Handlers are export function; declarations are export const. A page with no controller script at all is valid and builds as static HTML.

Pages reject attributes, slots, consume and formControl. There is no host element to declare attributes on, there is nothing above a page to consume from, and form association belongs to a component. A wrong export form or a rejected block is CORALITE-E107.

paths()

Dynamic routes must enumerate the parameter combinations to build. The function receives { app }, may be asynchronous, and returns an array of parameter objects. Each object is matched against the route pattern derived from the file name.

export async function paths () { const fs = await import('node:fs/promises') const files = await fs.readdir('src/data/posts') return files.map((file) => ({ id: file.replace(/\.json$/, '') })) } export async function server ({ route }) { const fs = await import('node:fs/promises') const raw = await fs.readFile(`src/data/posts/${route.params.id}.json`, 'utf8') return { post: JSON.parse(raw) } }

Return parameters, not paths. [{ path: '/posts/hello' }] is not a parameter object: path is an undeclared parameter, so it is CORALITE-E402. A non-array result is the same code, and so is a non-string value. Every declared parameter must be present in every entry, and no extra keys are allowed. The values always arrive in route.params, never as a separate argument.

Two enumerated objects with the same parameters are a build error. Deduplicate in paths() rather than relying on output order.

meta

meta is the page's public information surface: title, description, language, canonical URL, and any project-specific key. It uses the attribute schema, so it supports type, default, values and validate. required is rejected: a page has no external input, so declare a default instead.

export const meta = { title: { type: String, default: 'Untitled' }, description: { type: String, default: '' }, section: { type: String, values: ['Guide', 'Reference', 'Blog'] }, noIndex: { type: Boolean, default: false } }

Values seed state, so a token or getter can read them. Keys are not restricted to SEO fields: campaign, locale or version are equally valid.

Precedence is deterministic:

  • meta defaults seed state and page.meta.
  • Literal <title> and <meta> tags in the page remain authoritative over defaults.
  • Existing render state and onPageSet or onBeforePageRender patches override the defaults. The server() return value overrides last.
  • Returned keys update state only. Mutate page.meta directly when a handler must change metadata.
  • A schema entry without a default creates no state key and no page.meta entry.

server()

The page handler runs at build time with the page's context and returns an object merged into page state. Unlike a component, it can also stop the render and emit a redirect stub.

Key Notes
stateMeta defaults, page tags and values returned so far.
routeThe concrete route for this output, including params.
pageThe page object, including its exports.
sessionThe active build session.
signalThe build cancellation signal.
storeThe server store when store is configured.
appThe Coralite instance.

Plugin server.context is merged into the same object, so a handler destructures plugin keys directly.

Redirects

Returning __redirect writes a redirect stub instead of rendering the document. The value is an object with to and an optional status of 301 or 302.

export function server ({ state }) { if (state.legacySlug) { return { __redirect: { to: `/posts/${state.currentSlug}/`, status: 301 } } } }

A relative target must start with /; absolute http:// and https:// targets are allowed. Anything else fails the build.

cacheKey()

Dynamic pages render one output per paths() entry. Incremental builds key each output by its sorted route.params and a stable serialization of the state resolved after server(). Changing data for one record therefore rebuilds only that record's output and leaves the rest skipped.

Declare cacheKey when server() returns large or non-serializable state, or when the output depends on data that is not represented in state. The handler receives { route, state }, may be asynchronous, and must return a string or number. Its return value replaces the default key entirely, so include every field that identifies the output. Returning anything else is CORALITE-E404.

export function cacheKey ({ route, state }) { return `${route.params.id}:${state.revision}` }

The same export opts a static page into explicit cache invalidation. If it is omitted on a static page, only the source-file hash decides whether the page rebuilds.

The manifest records the resolved key per output. A cache-key change writes the page again; structural changes to paths() still add or remove outputs. Changing the key semantics invalidates older manifests through the manifest version, so the first build after an upgrade rebuilds once.

getters, style and provide

getters, style and provide behave as they do in components, with one difference each:

  • getters receive the same context as a component, but refs returns null during SSR and page-level refs during hydration. Use the getters reference for the context table.
  • style writes onto the document root, so a custom property declared here is visible site-wide. Prefer page style for theme values the whole document needs; put component-scoped values in the component.
  • provide makes the page the outermost provider. Every component on the page, at any depth, can consume it. See provide and consume.
export const style = { '--page-accent': ({ state }) => state.accent || '#06b6d4' }

client()

The page client handler runs once in the browser. It receives a narrower context than a component: there is no instance identifier, no attribute errors and no form API.

Key Notes
stateReactive page state. Writes update tokens and getters.
routeThe active route, including params.
rootdocument.documentElement.
refsResolves ref="name" anywhere in the document.
signalPage runtime signal. Pass it to listeners you add from here.
emitDispatches a bubbling, composed event from the document root.

export function client ({ refs, signal, emit }) { refs('shortcut').addEventListener('keydown', (event) => { if (event.key !== '/') { return } event.preventDefault() emit('search:open') }, { signal }) }

The page boundary

A page composes components and passes data through attributes or context. It must not reach into a component's DOM or read its internal state: that logic belongs in the component. Page code that queries component internals is a CORALITE-PAGE-201 violation.

When the page needs a value from a component, listen for an event the component emits, or provide the value downward. The page does not need to know how the component renders it.

Legacy definePage

export default definePage({ ... }) is still accepted for existing pages. It is the same configuration object as the flat exports, just wrapped. New pages use the named exports; the wrapper is retained only for backwards compatibility and gets no new options.

Diagnostics

  • CORALITE-E107 reports a wrong export form, a rejected block, or more than one page controller script.
  • CORALITE-E402 reports a paths() result that is not an array of parameter objects.
  • CORALITE-E404 reports a cacheKey() result that is not a string or number.
  • CORALITE-E401 reports request or response globals, which pages do not receive.
  • CORALITE-PAGE-201 reports page code that reaches into component internals.
