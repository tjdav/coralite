attributes

Stable

Declares the host attributes a component accepts, how they are coerced, and when they are written back to the DOM.

Runs at build time and in the browser.

The server validates the attributes present in page markup while rendering. The browser repeats the same pipeline whenever a host attribute changes with setAttribute or removeAttribute.

Signature

export const attributes: Record<string, AttributeSchema> type AttributeSchema = | StringConstructor | NumberConstructor | BooleanConstructor | Array<string | number | boolean> | { type?: StringConstructor | NumberConstructor | BooleanConstructor default?: any required?: boolean values?: Array<string | number | boolean> reflect?: boolean transform?: (value: any) => any validate?: (value: any) => boolean | string | void }

Declaration keys are camelCase. Coralite maps them to the kebab-case attribute on the host element, so userId is written as user-id and both spellings resolve to the same state key.

Schema options

Option Type Effect
type String · Number · Boolean Primitive constructor used to coerce the raw attribute string. Defaults to String, or is inferred from values.
default any Value applied when the attribute is absent. Setting a default with required: true raises CORALITE-E102.
required boolean Records a validation error when the attribute is missing instead of failing the build.
values array Enumeration of accepted values. A mismatch records an error listing the expected values.
reflect boolean Writes the coerced value back to the host attribute whenever state changes.
transform function Runs after coercion, before values and validate. Must be synchronous; returning undefined leaves the state key unset.
validate function Returns true or nothing on success, false for the default message, or a string for a custom message. Must be synchronous.

Attributes accept primitives only. Declaring { type: Object } or { type: Array } fails with CORALITE-E101. Fetch structured data in server(), or pass it down the tree with provide and consume.

Execution pipeline

Every mount and every host mutation runs the same six steps in order:

01
Required

Rejects a missing or null value.

02
Default and coerce

Applies default, then the primitive constructor.

03
Transform

Runs the synchronous transform callback.

04
Values

Checks the value against the enumeration.

05
Validate

Evaluates the synchronous predicate.

06
Apply

Writes state and the error_* tokens.

The pipeline is never aborted by a validation failure. A value that was supplied is kept in state so the UI can render around it, and the message is written to state.errors and the flat template tokens {{ error_<name> }} in both camelCase and kebab-case.

<template id="user-field"> <label for="age">Age</label> <input id="age" type="number" value="{{ age }}"> <span class="error">{{ error_age }}</span> </template> <script type="module"> export const attributes = { age: { type: Number, required: true, transform: (value) => Math.trunc(value), validate: (value) => value >= 18 || 'You must be 18 or older.' } } </script>

Reflection

Attributes are one-way by default: the DOM is the input, state is the result. Set reflect: true to keep the attribute in sync with state after client changes, which is how a component keeps a CSS selector such as ui-toggle[checked] working.

export const attributes = { checked: { type: Boolean, default: false, reflect: true } } export function client ({ state, refs, signal }) { refs('toggle').addEventListener('click', () => { state.checked = !state.checked }, { signal }) }

Only reflect values a stylesheet or consumer needs. Reflecting every attribute causes redundant DOM writes and makes host markup the second source of truth.

Validation errors

Attribute validation never aborts the render. Failures are recorded in two places:

  • state.errors maps the camelCase attribute name to the message, for example state.errors.userAge.
  • {{ error_<name> }} tokens are populated in both camelCase and kebab-case, for example {{ error_userAge }} and {{ error_user-age }}. They render an empty string when the value is valid.
  • The client context exposes the same dictionary as errors.

The dictionary is reactive. Writing to state.errors, deleting a key or replacing the whole object updates both token spellings and schedules a render. When every attribute is valid, Object.keys(state.errors).length === 0.

Template attribute toggling

When a single state token is bound to an element attribute, Coralite decides whether to write a value, write an empty presence attribute, or remove the attribute entirely.

  • Native boolean attributes: the 43 standard HTML boolean attributes and declared Boolean custom attributes use presence semantics. A falsy value removes the attribute; a truthy value writes an empty string, for example disabled="".
  • Core ARIA state: aria-expanded, aria-pressed, aria-checked and aria-selected format falsy values as "false" and keep "mixed". They are removed only for nullish or empty values.
  • Other ARIA attributes: falsy values remove the attribute, except numeric 0, which is preserved.
  • Standard attributes: values are written as strings. A nullish value removes the attribute, while an explicit empty string is preserved.

Diagnostics

  • CORALITE-E101 blocks Array and Object types.
  • CORALITE-E102 blocks required: true combined with default.
  • CORALITE-E103 blocks asynchronous transform and validate callbacks.
  • CORALITE-E104 blocks names that collide with framework context keys.
  • CORALITE-W401 reports a declared attribute that nothing reads.
