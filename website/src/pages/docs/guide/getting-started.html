Getting Started

Coralite is an HTML-first framework designed for building fast, static, and server-rendered web applications using native Web Platform standards. This guide covers project setup, directory structure, authoring your first component and page, and running core commands.

Coralite consists of two primary packages: coralite (the framework runtime and engine) and coralite-scripts (the build, development, and toolchain scripts). You can scaffold a new project using the official create-coralite initializer:

npm create coralite@latest my-app cd my-app npm install npm run dev

A standard Coralite application uses a simple, predictable directory layout:

my-app/ components/ site-header.html site-footer.html pages/ index.html public/ favicon.svg coralite.config.js package.json
  • components/ — Reusable HTML web components that can contain static markup, styles, and dynamic script blocks.
  • pages/ — Application routes rendered as HTML pages based on directory structure and file names.
  • public/ — Static assets (such as favicons, images, and fonts) served directly at the output root.
  • coralite.config.js — Framework configuration file for output directories, plugins, CSP, and build options.
  • package.json — Node package manifest declaring dependencies and framework lifecycle scripts.

Components in Coralite are authored as HTML files containing a <template> element, an optional <script type="module"> exporting defineComponent, and an optional <style> element.

The create-coralite scaffolder configures five core lifecycle scripts in package.json:

  • dev — Starts the local development server with live preview and instant reloading.
  • test — Executes the test suite across components and application logic.
  • build — Compiles pages, components, and static assets into optimized SSG output.
  • check — Runs static AST validation and type-checking across all templates and scripts.
  • fix — Applies automated AST codemods and fixers for diagnostic warnings.
