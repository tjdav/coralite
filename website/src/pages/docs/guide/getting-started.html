Getting Started

Guide

Learn how to install Coralite, set up a project, author your first component and page, and use essential framework scripts.

Coralite is an HTML-first application framework built on native Web Platform standards. The same output runs on the web, in desktop shells and in mobile shells, and plugins add the platform-specific edges. This guide covers project setup, directory structure, your first component and page, and the core commands.

1. Installation

Coralite ships as a single coralite package: framework runtime and engine, the coralite CLI (development server, build, and testing commands), the defineConfig configuration helper, and the plugin system. You can scaffold a new project using the official create-coralite initializer:

npm create coralite@latest my-app cd my-app npm install npm run dev

2. Project Structure

A standard Coralite application uses a simple, predictable directory layout:

my-app/ components/ site-header.html site-footer.html pages/ index.html public/ favicon.svg coralite.config.js package.json
  • components/ — Reusable HTML web components that can contain static markup, styles, and dynamic script blocks.
  • pages/ — Application routes rendered as HTML pages based on directory structure and file names.
  • public/ — Static assets (such as favicons, images, and fonts) served directly at the output root.
  • coralite.config.js — Framework configuration file for output directories, plugins, CSP, and build options.
  • package.json — Node package manifest declaring dependencies and framework lifecycle scripts.

3. First Component

Components in Coralite are authored as HTML files containing a <template> element, an optional <script type="module"> block with top-level named exports (export const attributes, export function server, export function client), and an optional <style> element.

<script type="module"> export const attributes = { title: { type: String, default: 'Hello' }, message: { type: String, default: 'Welcome to Coralite!' } } </script>

4. First Page

Pages are authored inside the pages/ directory. Pages can include a <script type="module"> with flat named exports such as export function server to manage build-time data loading via server().

{{ pageTitle }}

{{ headline }}

{{ description }}

<script type="module"> export function server () { return { pageTitle: 'Home — My Coralite Site', headline: 'Build once. Ship to web, desktop and mobile.', description: 'Coralite combines native Web Components with build-time SSR.' } } </script>

5. Scripts

The create-coralite scaffolder configures five core lifecycle scripts in package.json:

  • dev — Starts the local development server with live preview and instant reloading.
  • test — Executes the test suite across components and application logic.
  • build — Compiles pages, components, and static assets into optimized SSG output.
  • check — Runs static AST validation and type-checking across all templates and scripts.
  • fix — Applies automated AST codemods and fixers for diagnostic warnings.
