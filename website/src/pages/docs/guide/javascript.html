Client-Side JavaScript

Guide

How component client() blocks work: flat named exports, reactive state, refs, observers, events and the browser lifecycle.

Client logic lives in a component's <script type="module"> block. The compiler reads top-level named exports, so there is no wrapper function and no configuration object around them. The browser receives only the blocks that need to run there.

Pages orchestrate, components encapsulate.

A page may have its own client() for document-level concerns such as shortcuts or analytics, but it must not reach into a component's DOM. Cross-component behavior belongs in the components that own it, or in a parent component that coordinates them.

The component module

A component declares behavior with named exports. Handlers are export function; configuration is export const.

<template id="counter-button"> <button ref="button" type="button"> Clicked {{ count }} times </button> </template> <script type="module"> export const attributes = { initialCount: { type: Number, default: 0 } } export async function server () { const store = await import('./store.js') return { user: await store.currentUser() } } export const getters = { greeting: ({ state }) => `Hello, ${state.user.name}` } export function client ({ state, refs, signal, emit, observe }) { state.count = state.initialCount observe('count', (value, previous) => { console.log('count changed', previous, '→', value) }) refs('button').addEventListener('click', () => { state.count++ emit('count-updated', { count: state.count }) }, { signal }) } </script>

The legacy export default defineComponent({ ... }) wrapper still loads, but new components use the flat form. The wrapper adds no runtime behavior.

The client context

client() runs once per mounted instance and receives a single context object. Destructure what the block needs.

Key Purpose
stateRead/write reactive proxy. Writes schedule a render and re-evaluate dependent getters.
refsResolves ref="name" inside the instance, including owned slot content.
signalAborts on disconnect. Pass it to listeners, fetches and timers.
observeRuns a side-effect when a state key changes. Returns a disposer.
emitDispatches a bubbling, composed CustomEvent from the host.
updateCompleteResolves after the current update flush writes the DOM. Do not await it at the top of the block.
errorsLive attribute validation errors from state.errors.
instanceId, root, routeIdentity and location for the instance.
form helpersinternals, setFormValue, setValidity, checkValidity, reportValidity, onFormReset, onFormDisabled, onFormRestore. Effective when the component exports formControl = true. See formControl.
plugin keysclient.context from registered plugins is merged onto the context.
Custom elements belong in scanned client code

Create custom elements in component or page client(), or in plugin client functions. Coralite rewrites literal creation there and records the tags for dependency tracking. Dynamically imported helper modules are bundled but not scanned, so creation inside them needs the runtime fallback.

See the Imperative Components Reference for ownership, upgrade timing and troubleshooting.

State observation

Templates update automatically. observe is for the effects the template cannot express: canvas repaints, third-party widgets, analytics, or imperative DOM updates.

  • Synchronous state: the callback runs when the observed value changes and the new value differs from the previous one.
  • Async getters: the callback runs when the promise resolves. Stale resolutions are discarded if state changes while a resolution is in flight.
  • Mutation is forbidden: assigning state inside an observer can loop. Use a getter for derived values; development builds report CORALITE-E302.
  • Cleanup is automatic: observers are removed at disconnect. The returned disposer is for conditional teardown.
export const getters = { results: async ({ state, signal }) => { const response = await fetch(`/api/search?q=${state.query}`, { signal }) return response.json() } } export function client ({ state, observe }) { observe('score', (value, previous) => { console.log(`score changed from ${previous} to ${value}`) }) observe('results', (results) => { console.log('search results updated', results) }) }

Getters declared async are skipped during SSR, so the token renders empty in the initial HTML and resolves in the browser. Use them for interaction-driven data, not for content that must be present before JavaScript runs.

Reactivity and performance

Coralite uses a lazy deep proxy. Nested objects and arrays become reactive the first time they are read, so a large dataset does not pay the wrapping cost until a component touches it.

Templates are dumb on purpose. Instead of a Virtual DOM, Coralite replaces flat tokens directly and updates only the bindings that depend on the changed state. That is the same design decision described in Core Concepts.

Using external libraries

Load browser dependencies inside client(). Local and package imports are bundled; stylesheets use the same dynamic import and resolve to the injected link.

export async function client ({ refs, signal }) { const [, { default: confetti }] = await Promise.all([ import('canvas-confetti/confetti.css', { signal }), import('https://esm.sh/canvas-confetti@1.6.0') ]) refs('celebrate').addEventListener('click', () => { confetti() }, { signal }) }

Module-scope imports are not available inside client(). Referencing one is CORALITE-E301. Node globals such as process are CORALITE-E304.

Component communication

emit(name, detail?, options?) creates a native CustomEvent on the host with bubbles: true and composed: true. Parent components listen with a ref, and pages can listen at the document level.

export function client ({ state, emit }) { emit('user-updated', { id: state.userId, name: state.userName }) } export function client ({ refs, signal }) { const child = refs('userCard') child.addEventListener('user-updated', (event) => { console.log('user updated', event.detail.name) }, { signal }) }

emit returns false when a listener cancels a cancelable event. Pass { cancelable: true } if a parent may veto the action.
