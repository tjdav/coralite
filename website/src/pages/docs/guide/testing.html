Testing & Deployment

Shipping production-grade Coralite applications requires verifying component behavior at unit level, testing full-page hydration during end-to-end (E2E) workflows, deploying static artifacts to host platforms, and hardening application security with strict Content Security Policies (CSP).

Coralite provides isolated evaluation utilities via coralite/testing to unit test components and pages without launching a full browser instance or static server.

Use loadComponent(path, options) to evaluate a component's server(), getters, and context blocks in Node.js isolated VM contexts. You can pass mock state, route context, and custom context parameters.

import test from 'node:test' import assert from 'node:assert/strict' import { loadComponent } from 'coralite/testing' test('user-card component evaluates server state', async () => { const result = await loadComponent('src/components/user-card.html', { context: { route: { path: '/team', params: {} } } }) assert.equal(result.errors.length, 0) assert.ok(result.definition) })

Similarly, loadPage(path, options) isolates page definitions and returns evaluated route patterns, enumerated paths, and server return values.

import test from 'node:test' import assert from 'node:assert/strict' import { loadPage } from 'coralite/testing' test('blog page exports enumerated paths', async () => { const result = await loadPage('src/pages/blog/[slug].html') assert.equal(typeof result.definition.paths, 'function') })

For end-to-end verification in real browser environments (such as Playwright or Cypress), Coralite exposes hydration testing helpers when built in testing mode (mode: 'testing').

When mode is set to 'testing' (or when using coralite test), the browser exposes window.__coralite_test__ on the global scope:

  • window.__coralite_test__.ready: A Promise resolving when data-coralite-ready is set on <html> and all initial component client() controllers finish execution.
  • window.__coralite_test__.reset(): Clears localStorage, sessionStorage, IndexedDB databases, and service worker registrations without triggering a hard page reload.
  • window.__coralite_test__.flush(): Awaits active microtask DOM batch updates across all custom element instances.
import { test, expect } from '@playwright/test' test('counter button increments state post-hydration', async ({ page }) => { await page.goto('http://localhost:4200/') // 1. Wait for framework hydration readiness await page.evaluate(() => window.__coralite_test__.ready) // 2. Interact with hydrated component const button = page.locator('button[ref="counter"]') await button.click() // 3. Assert updated state in DOM await expect(button).toHaveText('Count: 1') })

Building a Coralite project with coralite build compiles all HTML pages, scoped CSS, component scripts, and public static assets into the target directory (default dist/).

The cleanUrls configuration setting in coralite.config.js dictates how page HTML files are structured in the output directory:

import { defineConfig } from 'coralite' export default defineConfig({ cleanUrls: true // Default: outputs dist/about/index.html (/about) })
  • cleanUrls: true (Directory Style, Default): Page src/pages/about.html builds to dist/about/index.html with route path /about.
  • cleanUrls: false (File Style): Page src/pages/about.html builds to dist/about.html with route path /about.html.

Because the output is pure static HTML, CSS, and client JS bundles, Coralite applications require zero Node.js server runtime. You can deploy the dist/ folder directly to any static web host or object storage CDN:

  • Netlify: Set publish directory to dist and build command to pnpm build.
  • Vercel: Configure output directory as dist with static framework preset.
  • Cloudflare Pages: Point build output directory to dist.
  • AWS S3 + CloudFront: Sync dist/ directly to your S3 bucket.

Coralite provides automated Content Security Policy generation to protect your site against Cross-Site Scripting (XSS) and code injection.

Enable and configure CSP directly in coralite.config.js:

import { defineConfig } from 'coralite' export default defineConfig({ csp: { enabled: true, hashAlgorithm: 'sha256', injectMeta: true, directives: { 'default-src': ["'self'"], 'script-src': ["'self'"], 'style-src': ["'self'"] } } })
  • SSG Hash Mode (Default): During build, Coralite computes cryptographic hashes (SHA-256) for all inline scripts, import maps, and styles, injecting <meta http-equiv="Content-Security-Policy" content="..."> into the document head.
  • SSR Nonce Mode: When rendering on demand, pass a per-request cryptographic nonce option to coralite.build(url, { nonce }) to propagate nonce attributes across framework scripts.
