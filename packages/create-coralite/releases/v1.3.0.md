## Release Overview

The 1.3.0 release adds Codeberg release tooling to the Coralite CLI. Static components can now compile to zero client JavaScript without dummy exports.

---

### Key Highlights

#### Codeberg releases, versioned archives, and tabbyAPI integration

The Coralite CLI now creates Codeberg releases with versioned release archives. It integrates tabbyAPI for release-related workflows. `create-coralite` v1.3.0 packages these CLI changes for new projects.

#### Zero-JS static components without dummy exports

Static components can omit `<script type="module">` blocks. Component module scripts that declare no recognized named exports compile as zero-JS static components. Empty or comment-only module scripts no longer cause parse errors.

Before:

```html
<template id="ui-card">
  <div class="card">
    <slot></slot>
  </div>
</template>

<style>
  :host {
    display: block;
  }
</style>

<script type="module">
  export const attributes = {};
</script>
```

After:

```html
<template id="ui-card">
  <div class="card">
    <slot></slot>
  </div>
</template>

<style>
  :host {
    display: block;
  }
</style>
```

Scripts without exports also compile as static components:

```html
<script type="module">
  // Helper notes or module-local utilities only.
</script>
```

These components compile to zero client lifecycle code.

---

### Internal Changes

#### Compiler evaluation

`evaluateDevelopment()` and `evaluateProduction()` return an empty component definition when a component module script contains no recognized named exports.

#### Parser normalization

`parse.js` normalizes empty sibling `<script type="module"></script>` tags instead of triggering a `Script tag must contain text` error.

#### Tests and documentation

Adds unit tests for empty, comment-only, and helper-only scripts in development and production. Updates `AGENTS.md`, template instructions, and documentation to clarify that static components require neither script blocks nor placeholder exports.
