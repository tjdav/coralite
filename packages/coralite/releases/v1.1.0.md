## Release Overview

Coralite 1.1.0 keeps compile-time static HTML and zero runtime JavaScript as the default output. It adds typed page state, lazy dependency stylesheets, flat page exports, and marker-based SSR token hydration.

---

### Key Highlights

#### Lazy dependency stylesheets

Coralite loads dependency CSS only when client code runs, keeping static HTML free of unused stylesheet requests. Coralite resolves dynamic CSS imports inside `client()` at build time and injects the matching `<link rel="stylesheet">` element only when the importing component, page, or client helper module executes in the browser.

* Build-time resolution bundles CSS with esbuild, resolves `@import`, rewrites `url()` assets, emits referenced images, fonts, and media files, applies configured PostCSS plugins, and minifies production CSS.
* Resolution includes local, relative, and bare-package CSS specifiers, including package files outside `package.json` exports.
* A stylesheet manifest maps deterministic handles to hashed CSS assets and optional link attributes.
* Runtime imports rewrite to `window.__coralite__.importCSS(...)`, deduplicate loads, preserve order, honor abort signals, and pass remote CSS URLs through without bundling.
* Coralite rejects static CSS imports, CSS imports outside `client()`, and invalid CSS import options with `CORALITE-E109`. Missing or unresolvable local CSS files fail the build with `CORALITE-E403`.
* Supported options include `media`, `nonce`, `crossorigin`, `referrerPolicy`, `referrerpolicy`, `signal`, `force`, and `with`.
* `signal` stops the awaiting caller from waiting but does not remove a shared stylesheet link while another caller still uses it.

```js
export async function client ({ signal }) {
  await import('acme-styles/dist/acme.css', { signal })
}
```

```js
export async function client ({ signal }) {
  await import('./local.css', {
    media: 'print',
    signal
  })
}
```

Coralite rejects:

```js
import 'acme-styles/dist/acme.css' // CORALITE-E109
```

The dynamic import resolves to a module-like result:

```js
const { default: sheet, link } = await import('acme-styles/dist/acme.css', { signal })
```

`sheet` is the loaded `CSSStyleSheet` when available, and `link` is the injected `<link rel="stylesheet">` element.

#### Declared page state with meta

Pages declare typed default state with `export const meta`. Coralite resolves meta defaults before `server()` runs, merges them into page state, and fills missing `page.meta` keys while literal `<head>` tags remain authoritative.

* The `meta` schema uses the same shape as component attributes: `type`, `default`, `values`, and `validate`/`transform`.
* Coralite rejects `required`, `Array` and `Object` types, and asynchronous `validate`/`transform` handlers.
* Invalid defaults, such as a non-numeric `Number` default, fail the build.
* `server()` receives both `state` and `page` context.
* Coralite still recognizes legacy `definePage({ meta })` blocks and migrates them to flat exports.
* `coralite/testing` `loadPage()` exposes `metaDefaults` and passes them into `server()`.

Before:

```html
<script type="module">
  export async function server () {
    return {
      title: 'Default title',
      count: 3
    }
  }
</script>
```

After:

```html
<script type="module">
  export const meta = {
    title: { type: String, default: 'Default title' },
    count: { type: Number, default: 3 },
    campaign: { values: ['organic', 'paid'], default: 'organic' }
  }

  export async function server ({ state, page }) {
    return {
      title: `${state.title} — live`,
      count: state.count * 2
    }
  }

  export const getters = {
    docTitle: ({ state }) => state.page.meta.title
  }
</script>
```

If a page already contains a literal `<title>` tag, `page.meta.title` keeps the literal value. The `meta` default still seeds state and fills missing metadata.

#### Marker-based SSR page tokens

SSR records page token positions with scoped `data-coralite-page-token` markers and serializes raw text and attribute templates into page config. The page runtime updates marked text nodes and attributes when state changes, including tokens on `<html>`, without relying on raw `{{ token }}` strings to survive hydration.

* Updates cover text content, element attributes, `<html>` attributes, and slotted children.
* Legacy raw-template updates remain as a fallback path.
* Fallback renders emit an empty token map.
* E2E coverage adds text, attribute, and `<html>` token regressions.
* `stripPageTokenMarkers(html)` removes internal marker attributes so exact-HTML assertions stay stable.
* Marker attributes are internal implementation details, not part of the public page authoring API.

```html
<html lang="{{ lang }}">
  <body data-count-label="{{ countLabel }}">
    <button ref="lang" type="button">
      lang: {{ lang }}
    </button>

    <script type="module">
      export async function server () {
        return {
          lang: 'en',
          count: 0
        }
      }

      export const getters = {
        countLabel: ({ state }) => `count: ${state.count}`
      }

      export function client ({ refs, state, signal }) {
        refs('lang').addEventListener('click', () => {
          state.lang = state.lang === 'en' ? 'fr' : 'en'
        }, { signal })
      }
    </script>
  </body>
</html>
```

After hydration, a click updates the `<html>` attribute, the `<body>` attribute, and the button text:

```html
<html lang="fr">
  <body data-count-label="count: 0">
    <button>lang: fr</button>
  </body>
</html>
```

#### Flat named exports for pages

Pages use the same flat named export model as components. Coralite recognizes `export function server`, `export const getters`, `export function paths`, and related page exports while retaining legacy `export default definePage({...})`.

* The default export takes precedence when both flat and legacy page exports are present.
* The evaluator, parser, validator, collection, testing, and declaration helpers support flat page exports.
* The validator rejects component-only keys on pages and applies mirrored form rules.
* `coralite fix --migrate-pages` adds a `definePage` to flat-export codemod and bails on unsupported input.

Before:

```html
<script type="module">
  export default definePage({
    async server () {
      return { title: 'Home' }
    }
  })
</script>
```

After:

```html
<script type="module">
  export async function server () {
    return { title: 'Home' }
  }
</script>
```

### Bug Fixes & Improvements

#### Node built-in global detection

`client()` code triggers `CORALITE-E304` when it references Node runtime globals such as `process`, `Buffer`, `global`, and `setImmediate`. Shared Web-platform globals such as `console`, `fetch`, `URL`, and `crypto` do not trigger the diagnostic. Local declarations and nested parameter shadows suppress false positives, and the pass runs for components and page inline scripts.

#### Type-checker Node global support

The type checker suppresses Node global errors only outside `client()` ranges and gates `compilerOptions.types` Node support on real project visibility. `paths()` and `server()` can use Node globals without `TS2580` or `TS2591` errors.

#### Hydration binding and signal fixes

Compiled binding updaters route through marker re-resolution, so replaced or late-arriving marked nodes receive updates. Getter dependency sets survive throwing evaluations, cached reads, and compiled updater reads, keeping nested and fan-out bindings current. Selective update paths mirror the same behavior, and the marker cache clears on teardown and reconnect.

* The reactive state proxy refreshes getter dependencies only when the getter actually runs.
* Derived getter updaters read `_stateRaw` so dependency tracking survives cached computed values.
* Unresolved bindings persist across unrelated state changes and retry only the affected tokens.
* Context proxies expose isomorphic plugins through `getOwnPropertyDescriptor`.

#### Router config options

The router plugin accepts `autoWrap` and `outletOnly` config options.

#### CLI and dev server fixes

CLI commands resolve against source under `--conditions=development`, and dynamic route parameters work in the dev and test servers.

#### Zero-JS static component hydration check

Coralite skips the testing hydration check for zero-JS static components.

#### Devtools and compiler fixes

Devtools setup preserves existing `window.__coralite__` properties, and the compiler retains attribute updaters by typing attributes in the hydration map.

### Internal Changes

#### Page meta render isolation

Coralite assembles effective `page.meta` on a cloned page object instead of writing defaults back into the collection page. Hook and server mutations stay render-scoped, and removing a default does not leave a stale value in long-lived processes.

#### Hydration proxy extraction

Coralite extracts `createIsoPluginProxy` for getter contexts, reducing repeated proxy setup in hydration code.

#### Style and test coverage

Element style blocks add blank lines between logical code blocks. Hydration and page meta tests cover compiled binding re-resolution, meta defaults, render isolation, and slotted token resolution.
