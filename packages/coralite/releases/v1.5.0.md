## Release Overview

Coralite v1.5.0 adds lazy on-demand rendering for dynamic routes in development and route-aware cache keys for incremental static builds. Production builds continue to compile all pages into zero-JS static HTML by default while rebuilding only modified dynamic outputs.

---

### Key Highlights

#### Lazy Dynamic Route Rendering in Development

`coralite dev` now renders dynamic routes on request instead of pre-rendering every enumerated output at startup, reducing startup time and memory usage on large sites while leaving production builds uncapped. Test mode uses the same per-output request filtering.

* Dev and test server startup in [server.js](https://github.com/tjdav/coralite/blob/main/packages/coralite/lib/cli/server.js) invokes `coralite.build()` with `{ dynamicPaths: [] }` to skip pre-rendering dynamic routes; incoming requests resolve `routeParams` via `resolveSource()` and pass `{ dynamicPaths: [routeParams] }` to the renderer in [renderer.js](https://github.com/tjdav/coralite/blob/main/packages/coralite/lib/server/renderer.js), which filters `enumeratedPaths` using `routeParamsKey()` in [route.js](https://github.com/tjdav/coralite/blob/main/packages/coralite/lib/server/route.js).
* `createPageCache()` in [page-cache.js](https://github.com/tjdav/coralite/blob/main/packages/coralite/lib/cli/page-cache.js) replaces the unbounded `Map` in [server.js](https://github.com/tjdav/coralite/blob/main/packages/coralite/lib/cli/server.js) with a bounded LRU cache (defaulting to `256` entries) that tracks and evicts alias keys such as `page.html` and `page/index.html` together.
* Development route and cache controls in [config.js](https://github.com/tjdav/coralite/blob/main/packages/coralite/lib/server/config.js), [create.js](https://github.com/tjdav/coralite/blob/main/packages/coralite/lib/server/create.js), and [core.js](https://github.com/tjdav/coralite/blob/main/packages/coralite/types/core.js) add `dev.routeFilter`, `dev.maxPages` (aliased as `dev.limit`), and `dev.maxCacheEntries` (`0` disables caching), backed by `applyDevRouteLimits()` in [route.js](https://github.com/tjdav/coralite/blob/main/packages/coralite/lib/server/route.js).
* File-change handling in [server.js](https://github.com/tjdav/coralite/blob/main/packages/coralite/lib/cli/server.js) reloads modified pages and fixture pages (`deleteItem` and `setItem`) and reapplies dev route limits during HMR so lazy requests do not render stale collection data.

```js
// coralite.config.js
import { defineConfig } from 'coralite'

export default defineConfig({
  pages: './src/pages',
  components: './src/components',
  output: './dist',
  dev: {
    // Filter enumerated dynamic routes before applying the cap
    routeFilter: ({ params }) => params.category !== 'archive',
    // Cap total dynamic outputs in development (alias: `limit`)
    maxPages: 100,
    // Limit the in-memory LRU page cache (0 disables caching)
    maxCacheEntries: 128
  }
})
```

#### Route-Aware Incremental Cache Keys

Incremental builds now track individual dynamic page outputs using route-aware cache keys instead of relying solely on source file hashes. When a single record changes, only that output rebuilds while unchanged routes skip rendering and carry forward their manifest metadata and tracked assets.

* Dynamic routes (`paths()`) are keyed by an `xxHash` of their sorted `params`, `path`, `pattern`, and deterministically serialized `server()` state via `stableSerialize()` in `createPageCacheKey()`.
* Both dynamic and static pages can export `cacheKey({ route, state })` to supply a custom `string` or `number` cache key; returning any other type fails the build with `CORALITE-E404`.
* `.coralite/manifest.json` now records `version` (`MANIFEST_VERSION = 2`), automatically invalidating stale manifests from earlier builds.
* `addRenderQueue()` and `CoraliteCollection.prototype.updateItem()` accept `revision` (`string | number`) as an alias for `cacheKey` on virtual pagination entries.

```html
&lt;!DOCTYPE html&gt;
&lt;html&gt;
  &lt;head&gt;
    &lt;title&gt;{{ title }}&lt;/title&gt;
  &lt;/head&gt;
  &lt;body&gt;
    &lt;h1&gt;{{ title }}&lt;/h1&gt;
  &lt;/body&gt;
&lt;/html&gt;

&lt;script type="module"&gt;
  export async function paths ({ app }) {
    const fs = await import('node:fs/promises')
    const path = await import('node:path')
    const files = await fs.readdir(path.join(app.options.projectRoot, 'data'))
    return files
      .filter((file) => file.endsWith('.json'))
      .map((file) => ({ id: file.replace('.json', '') }))
  }

  export async function server ({ route, app }) {
    const fs = await import('node:fs/promises')
    const path = await import('node:path')
    const raw = await fs.readFile(
      path.join(app.options.projectRoot, 'data', `${route.params.id}.json`),
      'utf8'
    )
    const record = JSON.parse(raw)
    return { title: record.title, revision: record.revision }
  }

  export function cacheKey ({ route, state }) {
    return `${route.params.id}:${state.revision}`
  }
&lt;/script&gt;
```

Plugins queuing virtual pagination entries can pass `revision` directly to `addRenderQueue()`:

```js
await app.addRenderQueue({
  pathname: 'posts/page-2.html',
  content: '&lt;h1&gt;Page 2&lt;/h1&gt;',
  revision: 42
}, buildId)
```
