## Release Overview

Coralite v1.2.0 establishes compile-time boolean and ARIA attribute reflection for static HTML pages, ensuring pre-rendered templates omit falsy attributes and serialize valid ARIA states without runtime JavaScript overhead. This release also introduces semantic page composition and component reuse standards to agent scaffolding, while consolidating runtime globals under a unified namespace.

---

### Key Highlights

#### Unified Boolean and ARIA Attribute Reflection for Pages

Pages now share identical attribute reflection semantics with components during static HTML rendering and dynamic client-side hydration. Single-token bindings (`{{ prop }}`) evaluate against HTML boolean specifications, ARIA state definitions, and custom element schemas rather than performing raw string interpolation. Pre-rendered HTML omits falsy boolean attributes entirely, eliminating invalid DOM states such as `disabled="false"` that native browsers interpret as active.

* **Shared Reflection Engine**: [`lib/shared/tags.js`](file:///home/thomas/Projects/coralite/packages/coralite/lib/shared/tags.js#L104-L177) exports [`resolveBooleanOrAriaAttribute()`](file:///home/thomas/Projects/coralite/packages/coralite/lib/shared/tags.js#L104-L131), [`applyAstBoundAttribute()`](file:///home/thomas/Projects/coralite/packages/coralite/lib/shared/tags.js#L133-L152) for build-time AST manipulation, and [`applyDomBoundAttribute()`](file:///home/thomas/Projects/coralite/packages/coralite/lib/shared/tags.js#L154-L177) for client DOM updates.
* **Static SSR Resolution**: [`lib/server/renderer.js`](file:///home/thomas/Projects/coralite/packages/coralite/lib/server/renderer.js#L1573-L1615) evaluates single-token attribute bindings against custom element schemas and strips falsy boolean attributes (`false`, `null`, `undefined`, `0`, `''`) directly from the static AST output.
* **ARIA Normalization**: ARIA boolean states (`aria-expanded`, `aria-hidden`, `aria-checked`, `aria-pressed`) normalize truthy values to `"true"`, falsy values to `"false"`, and remove attributes when values resolve to `null` or `undefined`.
* **Direct Client Updates**: [`lib/client/page-runtime.js`](file:///home/thomas/Projects/coralite/packages/coralite/lib/client/page-runtime.js#L115-L125) replaces full-tree DOM crawling (`updateLegacyPageTokens`) with targeted DOM mutations, reducing hydration time and reactive flush overhead.

**Page Definition (`src/pages/dashboard.html`)**

```html
<button
  disabled="{{ isDisabled }}"
  aria-expanded="{{ isExpanded }}"
  aria-label="{{ label }}">
  Toggle Panel
</button>
<ui-modal open="{{ isModalOpen }}"></ui-modal>

<script type="module">
  export const meta = {
    isDisabled: false,
    isExpanded: false,
    label: null,
    isModalOpen: false
  }

  export function client({ state }) {
    // Dynamic mutations reflect directly to DOM attributes:
    // state.isDisabled = true  -> renders disabled=""
    // state.isDisabled = false -> removes disabled attribute
  }
</script>
```

**Rendered HTML & DOM Output**

| Attribute Binding | State Value | Before (String Interpolation) | After (Unified Reflection) |
| :--- | :--- | :--- | :--- |
| `disabled="{{ isDisabled }}"` | `false` | `<button disabled="false">` *(element disabled)* | `<button>` *(attribute removed)* |
| `disabled="{{ isDisabled }}"` | `true` | `<button disabled="true">` | `<button disabled>` *(boolean presence)* |
| `aria-expanded="{{ isExpanded }}"` | `false` | `<button aria-expanded="false">` | `<button aria-expanded="false">` *(normalized)* |
| `aria-label="{{ label }}"` | `null` | `<button aria-label="">` | `<button>` *(attribute removed)* |
| `open="{{ isModalOpen }}"` *(custom boolean)* | `false` | `<ui-modal open="false">` | `<ui-modal>` *(attribute removed)* |

#### Page Composition and Component Reuse Rules for Agent Scaffolding

Agent scaffolding generated by `coralite init-agent` now directs coding assistants to prioritize semantic HTML structures, deduplicate UI patterns, and adopt modern top-level named exports across [`AGENTS.md`](file:///home/thomas/Projects/coralite/AGENTS.md), `.cursorrules`, `.cursor/rules/coralite.mdc`, and `CLAUDE.md`.

* **Modern Named Exports**: Page guidelines standardize on `export function` (`paths`, `server`, `client`, `onError`) and `export const` (`meta`, `getters`, `style`, `provide`), deprecating `export default definePage({ ... })` to legacy compatibility mode.
* **Semantic HTML First**: Scaffolding rules prioritize standard semantic elements (`<header>`, `<main>`, `<article>`, `<section>`, `<nav>`) over arbitrary container `<div>` tags or redundant custom element wrappers for static content.
* **Component Reuse & De-duplication**: Guidelines instruct agents to inspect `src/components/` before generating new markup, preventing duplicate UI patterns across static pages.
* **Slot Projection**: Enforces explicit `<slot>` projection when nesting children inside reusable custom elements.
* **CLI Test Verification**: [`packages/coralite/tests/unit/lib/cli.spec.js`](file:///home/thomas/Projects/coralite/packages/coralite/tests/unit/lib/cli.spec.js) validates that agent configuration files output updated page export forms and composition guidelines.

**Before: Legacy `definePage` and Duplicate Markup**

```html
<!-- src/pages/about.html -->
<!-- Duplicating navigation markup instead of reusing components -->
<div class="site-header">
  <div class="brand">My App</div>
  <ul class="nav-links">
    <li><a href="/">Home</a></li>
    <li><a href="/about">About</a></li>
  </ul>
</div>

<div class="page-content">
  <h1>About Us</h1>
  <p>Welcome to our application.</p>
</div>

<script type="module">
  import { definePage } from 'coralite'

  export default definePage({
    getters: {
      title: () => 'About Us'
    },
    async server ({ state }) {
      state.loadedAt = Date.now()
    }
  })
</script>
```

**After: Modern Named Exports and Component Composition**

```html
<!-- src/pages/about.html -->
<header>
  <!-- Reusing existing project custom element from src/components/site-header.html -->
  <site-header></site-header>
</header>

<main>
  <!-- Standard semantic HTML for static structure and text -->
  <article>
    <h1>About Us</h1>
    <p>Welcome to our application.</p>
  </article>
</main>

<script type="module">
  export const meta = {
    title: 'About Us'
  }

  export async function server ({ state }) {
    state.loadedAt = Date.now()
  }
</script>
```

### Internal Changes

#### Runtime and VM Global Namespace Consolidation

Browser runtime globals and Node VM execution environments now reside under the single, non-enumerable `window.__coralite__` and `globalThis.__coralite__` namespaces. Structured sub-domains organize internal APIs across `config`, `state`, `dom`, `plugins` (such as [`window.__coralite__.plugins.router`](file:///home/thomas/Projects/coralite/packages/coralite/types/globals.js#L18)), `lifecycle` (`lifecycle.hydrated`), `devtools`, and `test`. Centralized definitions in [`packages/coralite/types/globals.js`](file:///home/thomas/Projects/coralite/packages/coralite/types/globals.js) and [`packages/coralite/lib/client/utils/runtime.js`](file:///home/thomas/Projects/coralite/packages/coralite/lib/client/utils/runtime.js) prevent global namespace pollution and ensure deterministic runtime sandboxing.

#### Documentation and Agent Invariant Alignment

Framework guides and [AGENTS.md](file:///home/thomas/Projects/coralite/AGENTS.md#L155) now codify the single global namespace rule as a strict invariant, prohibiting ad-hoc properties on `window` or `globalThis`. Documentation updates synchronize LLM full references and E2E testing guides with the consolidated testing (`window.__coralite__.test`) and lifecycle settlement APIs.
